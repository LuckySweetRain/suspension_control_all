# suspension_control_all

Pure Python comparison framework for half-car active suspension control.

Controllers:

- PID without road preview
- SPDF without road preview
- Nonlinear MPC with road preview
- Transformer-TD3 with road preview
- Transformer-DDPG with road preview
- Transformer-SAC with road preview
- Transformer-PPO with road preview

Research direction:

- The current thesis route is direct road-preview active-suspension control: SPDF as the completed classical baseline, BP-NMPS as conservative MPC parameter scheduling, and SI-RPPO as the safe-teacher-gated, projection-aware PPO policy-network contribution. See `docs/thesis_workflow_index.md`.
- The current control route directly uses already perceived road unevenness / road preview sequences; Chrono vision, PreScan contour extraction, and VLA-style platforms are treated as future extensions rather than the thesis core. See `docs/direct_road_preview_control_plan.md`.
- Thesis-ready evidence files and reproduction commands are indexed in `docs/thesis_evidence_package.md`.
- Thesis readiness, export, and final-template staging are handled by `scripts/check_thesis_readiness.py`, `scripts/export_thesis_package.py`, and `scripts/stage_thesis_template_import.py`.
- The MPC-parameter-learning branch uses a baseline-preserving neural MPC parameter scheduler (BP-NMPS) to adapt reduced full-car MPC-lite gains from road/scenario context. See `docs/mpc_parameter_policy_plan.md`.
- Current BP-NMPS evidence and claim boundaries are logged in `docs/bp_nmps_experiment_log.md`.
- The thesis-facing evidence matrix is generated by `scripts/build_thesis_claim_matrix.py` and written to `docs/thesis_claim_matrix.md`.
- The SI-RPPO ablation entry point is `scripts/run_si_rppo_ablation.py`, covering PPO from scratch, BC-PPO, residual BC-PPO, and safe residual BC-PPO.
- Current SI-RPPO experiment results and interpretation are logged in `docs/si_rppo_experiment_log.md`.
- `scripts/build_si_rppo_gate_evidence.py` summarizes the safe-teacher improvement gate by scenario and writes Markdown, CSV, a LaTeX table, and a Chinese method summary linking gate activation to return, unsafe steps, action smoothness, and projection reliance.

Environments:

- `HalfCarEnv`: fast pure-Python RK4 half-car environment for controller comparison.
- `MuJoCoHalfCarEnv`: MuJoCo rendering wrapper around `HalfCarEnv`; dynamics still come from the Python model.
- `MuJoCoVehicleEnv`: MuJoCo dynamics environment for RL. It models chassis heave/pitch, front/rear unsprung masses, passive suspension/tire spring-damper tendons, active suspension force actuators, moving road anchors, and road preview observations.
- `MuJoCoFullCarEnv`: MuJoCo full-car vertical dynamics environment. It adds chassis roll, four unsprung masses, four road anchors, correlated/independent left-right road excitation, axle-level or four-corner active control, and optional preview/perception error injection.

Road profiles:

- ISO 8608 random roads
- bump roads
- sine roads
- step roads
- potholes
- table-driven external road data
- CSV/text road files with `time,height` columns
- composite roads built from multiple components

The MuJoCo full-car corner config can train from already perceived road height profiles instead of extracting road contours inside PreScan. `road_preview` is the delayed/noisy preview seen by the controller, while `road_preview_clean` is retained in `info` for ablation and diagnostics. RL actions are treated as actuator force commands; the full-car environment can apply configurable first-order actuator lag and rate limits before the force reaches MuJoCo.

Full-car safety constraints are configured with `safety_limits`, including suspension travel, pitch, roll, wheel displacement, unsafe penalty, and optional episode termination on unsafe states. Validation reports include per-scenario safety violation counts.

Tune the reduced full-car MPC-lite gains before replacing the sampler with an RL parameter policy:

```bash
python scripts/tune_mpc_parameters.py --config configs/mujoco_full_car_corner.yaml --out results/mpc_parameter_tuning --trials 32 --scenario-limit 3
python scripts/train_mpc_parameter_policy.py --config configs/mujoco_full_car_corner.yaml --out results/mpc_parameter_policy --iterations 8 --population 16 --scenario-limit 3
python scripts/train_mpc_parameter_neural_policy.py --config configs/mujoco_full_car_corner.yaml --out results/mpc_parameter_neural_policy --episodes 32 --batch-size 4 --scenario-limit 3 --anchor-coef 0.1 --anchor-final-coef 0.02 --elite-bc-coef 0.05 --deployment-gate --baseline-penalty-weight 1.0 --unsafe-penalty-weight 5.0 --suspension-penalty-weight 1.0 --actuator-penalty-weight 0.2
python scripts/run_mpc_parameter_learning_benchmark.py --config configs/mujoco_full_car_corner.yaml --out results/mpc_parameter_learning_benchmark --tuning-trials 16 --cem-iterations 8 --cem-population 16 --neural-episodes 32 --neural-batch-size 4 --neural-anchor-coef 0.1 --neural-anchor-final-coef 0.02 --neural-elite-bc-coef 0.05 --neural-deployment-gate --scenario-limit 3 --eval-scenario-offset 3 --eval-scenario-limit 2
python scripts/run_mpc_parameter_seed_sweep.py --config configs/mujoco_full_car_corner.yaml --out results/mpc_parameter_seed_sweep --seeds 42,43,44 --tuning-trials 8 --cem-iterations 4 --cem-population 8 --neural-episodes 16 --neural-batch-size 4 --neural-anchor-coef 0.1 --neural-anchor-final-coef 0.02 --neural-elite-bc-coef 0.05 --neural-deployment-gate --scenario-limit 3 --eval-scenario-offset 3 --eval-scenario-limit 2 --min-support-rate 0.8 --max-mean-policy-delta 0.0 --max-mean-unsafe-delta 0.0
```

`train_mpc_parameter_policy.py` treats MPC-lite gain scaling as a one-step CEM parameter-policy problem. `train_mpc_parameter_neural_policy.py` uses a small PyTorch Gaussian policy network to map baseline gains and road/scenario summary features to normalized MPC gain scales, giving a context-adaptive MPC parameter scheduler rather than one fixed gain set. Its mean-action head is zero-initialized and can use an anchor regularizer, so the deterministic policy starts as fixed MPC-lite and only learns residual gain shifts when training evidence supports them. Passing `--anchor-final-coef` linearly anneals that regularizer across policy updates, which keeps early training baseline-preserving while allowing later updates to search for measurable improvement. Passing `--elite-bc-coef` distills positive-advantage sampled gain actions into the deterministic policy mean, so good exploratory MPC parameters can become deployable BP-NMPS behavior. Passing `--deployment-gate` uses the training/calibration scenarios to decide whether the learned deterministic policy is safe to deploy; if it is worse than fixed MPC-lite there, the checkpoint falls back to fixed MPC-lite on held-out evaluation and controller rollout. Its optional baseline-aware penalty discourages policies that degrade fixed MPC-lite comfort, safety, suspension travel, or actuator effort. `run_mpc_parameter_learning_benchmark.py` writes the comparison CSV and Markdown report for the fixed MPC-lite, random-search, CEM-policy, and neural-policy variants, including score deltas and mean comfort, safety, suspension, and actuator metrics. `run_mpc_parameter_seed_sweep.py` repeats the benchmark across seeds and reports separate non-inferiority and improvement claim statuses, so matching fixed MPC-lite is not misreported as a performance gain. It also writes `mpc_parameter_seed_sweep_table.tex` for thesis/paper tables. Use `--eval-scenario-offset` and `--eval-scenario-limit` to evaluate final policies on held-out scenarios.

After training, the neural MPC parameter scheduler can be evaluated through the common controller factory as `BP_NMPS`, `neural_mpc_parameter`, or `mpc_parameter_policy` by passing the policy checkpoint.

```bash
python scripts/evaluate_all.py --config configs/mujoco_full_car_corner.yaml --checkpoints bp_nmps=latest --out results/bp_nmps_eval
python scripts/summarize_mpc_parameter_schedule.py --result-dir results/bp_nmps_eval
python scripts/build_mpc_parameter_schedule_evidence.py --summary results/mpc_parameter_seed_sweep_formal_gate/mpc_parameter_seed_sweep_summary.json --out results/bp_nmps_schedule_evidence
python scripts/run_bp_nmps_preview_robustness.py --summary results/mpc_parameter_seed_sweep_formal_gate/mpc_parameter_seed_sweep_summary.json --out results/bp_nmps_preview_robustness
```

BP-NMPS trajectory CSV files include `mpc_param_action_*` and `mpc_param_gain_*` columns so the learned gain schedule can be inspected alongside suspension responses. The schedule summary also reports gain scales and percentage changes relative to the base MPC-lite gains.
For the formal seed sweep, `build_mpc_parameter_schedule_evidence.py` aggregates the deployed final gain schedule across seeds, including gate-on fallback rows and gate-off learned gain deltas.
`run_bp_nmps_preview_robustness.py` reruns fixed MPC-lite and deployed BP-NMPS under clean, nominal-error, and strong-error preview cases so the thesis can separate nominal gain-scheduling evidence from preview-corruption robustness evidence.
